# JFFS scripts (reference copies)

These are the files `xt8-bootstrap.sh` writes into `/jffs/scripts/` on the XT8. They are here so you can read them without the router. **Do not copy them to the router by hand**; run the bootstrap script, which also keeps other add-ons' lines (Skynet) in the shared files.

| File | Runs when | What it does |
| --- | --- | --- |
| `homenet.conf` | read by the others | Addresses: IPv6 prefix, Pi-hole, guest subnet, the k3s nodes that may run Homebridge |
| `dnsmasq.postconf` | every dnsmasq start | Turns local-only IPv6 on for `br0` and advertises the Pi-hole as the only IPv6 DNS server |
| `firewall-start` | every firewall restart | IPv6 filter rules, and the rules that let Homebridge reach the guest/IoT network |
| `kasa-guest-allow.sh` | called by the two below | The `ebtables` rules that let Kasa replies through the guest isolation |
| `service-event-end` | after any router service event | Re-runs `kasa-guest-allow.sh` after a Wi-Fi restart wipes the `ebtables` rules |

On the real router, `firewall-start` also has a Skynet line above the marked block. These copies were generated by running the bootstrap script against an empty folder, so they show only the block this repo owns.

The AiMesh node has its own small script and reference file in [`../node/`](../node/); nothing in this folder is installed on the node.

The live router's `dnsmasq.postconf` is longer than the copy here (it had a `quiet-ra` line at line 25 until 7 October, outside this repo's block). Read the live file with `cat /jffs/scripts/dnsmasq.postconf` on the router, or take `sh /jffs/xt8-bootstrap.sh backup`, to see the rest.

Explanation of every line: [docs/02-router-xt8.md](../../../docs/02-router-xt8.md).
